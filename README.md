# Kino.kz → Telegram через GitHub Actions

Монитор фильма **Avengers: Doomsday / «Мстители: Доктор Дум» / «Мстители: Судный день»** в Алматы:

- **Chaplin MEGA Alma-Ata**, Розыбакиева, 247А (kino.kz ID 837).
- **Cinemax Dostyk Multiplex**, ТРЦ «Достык Плаза» (ID 825).

Ticketon, другие кинотеатры, Docker и VPS не используются. После настройки MacBook можно выключить. Код готов для загрузки в GitHub, но сам по себе скачанный архив ещё не включает мониторинг.

## Запуск без установки Python на компьютер

### 1. Создайте Telegram-бота

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте имя и username, заканчивающийся на `bot`.
3. Скопируйте выданный токен. Не публикуйте его в коде, issue или переписке.
4. Откройте своего нового бота и нажмите **Start**, затем отправьте ему `Привет`.

### 2. Узнайте chat_id

В браузере откройте адрес `https://api.telegram.org/bot<ТОКЕН>/getUpdates`, заменив `<ТОКЕН>` своим токеном без угловых скобок.
В ответе найдите сообщение `Привет` и скопируйте число из `result → message → chat → id`. Это ваш `TELEGRAM_CHAT_ID`.

Если `result` пустой, отправьте боту новое сообщение и обновите страницу. Для нового бота webhook не настроен; если используете старого бота с webhook, создайте отдельного через BotFather. Не пересылайте адрес с токеном; после настройки удалите его из истории браузера.

### 3. Создайте GitHub-репозиторий

1. В GitHub нажмите **New repository**, назовите его, например, `kino-monitor`, создайте README. Можно выбрать Private; учтите лимит минут Actions своего тарифа.
2. Распакуйте архив. Загрузите **содержимое** папки `kino-monitor` в корень репозитория через **Add file → Upload files**: `main.py`, `config.yaml`, `requirements.txt`, `README.md`, папку `tests` и `.gitignore`.
3. Отдельно создайте через **Add file → Create new file** файл `.github/workflows/monitor.yml` и вставьте в него содержимое одноимённого файла из архива. Папка `.github` скрытая, обычная загрузка может её пропустить.
4. Сохраните файлы в основной ветке (`main`). Файл `main.py` должен лежать прямо в корне, а не внутри дополнительной папки `kino-monitor`.

### 4. Добавьте два секрета

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**:

| Name | Secret |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен BotFather |
| `TELEGRAM_CHAT_ID` | Число из `message.chat.id` |

Токен и chat_id читаются только из переменных окружения. В `config.yaml`, `state.json` и ветку состояния они не записываются.

### 5. Проверьте разрешения и запустите

1. **Settings → Actions → General**: разрешите GitHub Actions. Workflow запрашивает `contents: write` для отдельной ветки состояния. Если политика организации запрещает запись, администратор должен её разрешить. Не защищайте ветку `monitor-state` от записи этого workflow.
2. **Actions → Kino monitor → Run workflow**, выберите `main`, включите **Только тестовое сообщение Telegram**. В Telegram должно прийти подтверждение.
3. Снова **Run workflow**, теперь без галочки теста. Этот запуск проверит kino.kz и пришлёт находки либо «Работаю, билетов пока нет».
4. Убедитесь, что запуск зелёный и появилась ветка **monitor-state** с `state.json`. Далее расписание работает автоматически.

Тестовый режим не опрашивает сайт и не изменяет историю уведомлений. Остановить монитор: **Actions → Kino monitor → … → Disable workflow**. Удалять токен или исходники для остановки не нужно.

## Что проверено на сайте

24 ноября 2026 года публичные JSON-запросы проверены напрямую, без авторизации и браузерной автоматизации:

- `GET https://kino.kz/api/trpc/sessions.findMovies` с `input={"json":{"startDate":"2026-11-24","endDate":"2027-03-24"}}`.
- `GET https://kino.kz/api/trpc/sessions.getSessions` с `input={"json":{"id":12344,"date":"2027-01-07"}}`.
- Cookie `city=2` выбирает Алматы. Ответ tRPC находится в `result.data.json`.

Методы и параметры найдены в публичных JS-модулях сайта. `findMovies` возвращает список; `getSessions` — объект с `sessions` и `available_dates`. Скрипт сначала проверяет премьерную дату (после премьеры — сегодня), затем **все будущие даты из available_dates**, включая предпоказы. Для пустых дат сайт допускает `sessions: null`.

[Карточка фильма](https://kino.kz/ru/movie/12344) называется «Мстители: Доктор Дум», оригинальное название — Avengers: Doomsday. В JSON премьера в Казахстане — **7 января 2027**. ID фильма не зашит в поиск: используется совпадение ключевых слов.

В проверенном API были даты 7–10 января и сеансы других площадок. Полный `--dry-run` вернул `[]`: подходящих сеансов в двух выбранных кинотеатрах на момент проверки не было. Это результат проверки на указанную дату, а не обещание текущего наличия.

Ссылки строятся так же, как на сайте: `/ru/movie/{movie_id}/tickets/{session_id}?cityId=2&cinemaId=...`. Используется публичное поле **session_id**, а не внутреннее **id**. Время берётся из `session_date` + `hour` + `minutes`: сайт отображает именно эти локальные часы. Поле `session_date_tz` не используется для пересчёта UTC.

Скрипт уведомляет о сеансе с `session_type == 1` (тип продажи, используемый клиентом сайта). Он не бронирует места и не запрашивает схему зала: наличие конкретных свободных кресел и возможность окончательной покупки проверяются по ссылке. Внутренний API не имеет гарантии неизменности; HTML-заглушка, ошибки API и неизвестная структура считаются сбоем, а не отсутствием билетов.

## Настройки

В `config.yaml` вынесены город, часовой пояс, ключевые слова, премьера, интервал, разброс, таймауты и ретраи.

В `keyword_groups` достаточно одного совпадения внутри каждой группы, но совпасть должны все группы. Например, у фильма должны быть и `avengers/мстители`, и `doomsday/судный день/доктор дум`. Это исключает другие части «Мстителей».

Для Chaplin требуются Chaplin + MEGA + Alma-Ata/Розыбакиева. MEGA Park и ADK исключены явно. Для Dostyk требуются Cinemax + Dostyk: «Арман» на проспекте Достык не подходит. Дополнительно проверяются координаты площадки в районе Алматы. ID кинотеатров приведены для сверки, сам фильтр работает по названиям.

## Расписание и нагрузка

Cron `2-57/5 * * * *` запускает workflow каждые пять минут, со смещением от начала часа. Сам скрипт делает один цикл и завершает работу. Между циклами хранится ближайшее разрешённое время `300 ± 30` секунд; ранний запуск ждёт до 60 секунд или пропускается. Между запросами разных дат есть пауза. Сетевые ошибки и HTTP 5xx повторяются до двух раз с backoff; HTTP 429 не повторяется в текущем цикле.

**GitHub Actions не гарантирует точные пять минут:** очередь, задержки и пропуски запусков увеличивают интервал. При задержанном cron отрицательный jitter технически не позволяет запуститься раньше выдачи runner. Эти ограничения нельзя устранить Python-кодом. В публичных неактивных репозиториях расписание может отключиться через 60 дней — проверьте, что workflow включён перед премьерой. [Документация GitHub о schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

288 запусков в сутки — около 8 640 запусков за 30 дней. В приватном репозитории это может превысить включённые минуты тарифа даже при коротких проверках. Посмотрите текущие лимиты в Billing/Actions; при исчерпании квоты мониторинг остановится. Более редкий cron экономит минуты, но увеличивает задержку уведомлений.

## Состояние, дубли и ошибки

- В `state.json` хранится хеш сайта, фильма, кинотеатра, публичного ID сеанса и даты/времени. Новое время или новый ID — новая находка. Повторное появление того же сеанса не создаёт уведомление.
- Отмечаем доставленным только после успешного ответа Telegram; файл записывается атомарно после каждого сообщения.
- Каждый run получает новый неизменяемый cache key. Свежий кэш восстанавливается по префиксу. Дополнительно файл сохраняется **в отдельную ветку monitor-state**, основной код не меняется. Ветка сохраняет историю при удалении/вытеснении кэша. При наличии двух копий используется более новая по `next_poll`.
- Запуски сериализованы `concurrency`, работающий run не отменяется следующим. Состояние сохраняется и после обычной ошибки проверки. Git push выполняется без force.
- После трёх последовательных ошибок сайта/JSON/полностью пустого расписания отправляется одно предупреждение. После восстановления — одно подтверждение. Отсутствие только нужных кинотеатров при нормальном расписании других площадок — штатное ожидание, не ошибка.
- Раз в 24 часа после успешной проверки отправляется heartbeat. После находок текст сообщает количество сеансов; во время сбоя не утверждает, что билетов нет.
- Если Telegram недоступен, сообщение остаётся недоставленным, run становится красным. Проверяйте уведомления GitHub о сбоях: бот не сможет сообщить о поломке самого Telegram, отключённом Actions или исчерпанной квоте.

Абсолютное exactly-once невозможно: если Telegram принял POST, но ответ потерялся, либо runner аварийно завершился до внешнего сохранения state, возможен повтор. После неоднозначного сетевого сбоя Telegram POST не повторяется. После явного 429 допускается один повтор через retry_after + 1 секунду, если пауза не больше 60 секунд; более длительный лимит переносит следующий обычный цикл. Между успешными уведомлениями выдерживается не менее 1,1 секунды. Таймаут чтения Telegram — минимум 60 секунд. При удалении и ветки состояния, и кэшей история теряется. Повреждённое состояние не сбрасывается автоматически.

## Команды для разработки (не нужны для GitHub-запуска)

Python 3.12+:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN='токен'
export TELEGRAM_CHAT_ID='chat_id'
python main.py --test
python main.py
```

Один запуск — один цикл; постоянного процесса на компьютере нет.

```bash
python main.py --dry-run                 # Только kino.kz, без Telegram и state
python -m unittest discover -s tests -v  # Офлайн-тесты
```

Проверены 17 тестов (включая диагностику Telegram, паузу retry_after и ограниченный повтор): названия, исключения кинотеатров, город, тип продажи, публичный ID, локальное время, обход всех дат, дубли, ошибка отправки, предупреждение/восстановление, heartbeat и повреждённое состояние.

## Если сайт изменится

Откройте фильм в браузере, выберите Алматы и дату → DevTools → Network → Fetch/XHR. Найдите запросы `sessions.findMovies` и `sessions.getSessions`. Для ремонта нужны URL, query-параметр `input` и JSON Response. Не присылайте Authorization, токен Telegram, полный HAR с личными данными или cookies авторизации. Сейчас Playwright не требуется: API отвечает на обычные GET-запросы.

Telegram использует [официальные методы Bot API getUpdates и sendMessage](https://core.telegram.org/bots/api). Правила [кэшей GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manage-caches) допускают удаление старых записей, поэтому кэш дополнен веткой состояния.
